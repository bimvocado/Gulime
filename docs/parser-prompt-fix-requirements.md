# 파서 프롬프트 개선 요구사항 (v1)

`scripts/measure_accuracy.py`로 41개 매칭 상품을 내용 기반 매칭 후 대조한 결과, 파서 쪽에서
같은 패턴의 오류가 반복적으로 나타났다. 아직 프롬프트 자체는 수정하지 않았고, 이 문서는
**지금 확정된 것만** 다음 프롬프트 개정 때 반영해야 할 요구사항으로 정리한다.

이력·자격 조건의 resource 처리 규칙(FIRST_TRADE 등을 resource=NONE으로 통일하는 건)은
하람 확인 대기 중이라 이번 정리에서는 제외했다. 확정되면 별도 섹션으로 추가한다.

총 3건(threshold) + 15건(UNCONDITIONAL 남발) + 16건(자원 오태깅) = **34건**.

---

## 1. threshold 자릿수 버그 (3건)

`data/accuracy_report.json`의 `wrong_cases` 중 `field: "threshold"`이고 정답 대비 파싱값이
정확히 10배 축소된 케이스만 추림 (만원 단위를 원 단위로 환산하는 과정에서 자릿수가 틀어진
버그. "300만원"이 `3000000`이 아니라 `300000`으로, 즉 "30만원"으로 파싱됨).

| 상품 | 은행 | 조건 | 정답 threshold | 파싱 threshold |
|---|---|---|---|---|
| 미즈월복리정기예금 | 광주은행 | 요구불예금 평잔 | 3,000,000 | 300,000 |
| 미즈월복리정기예금 | 광주은행 | 신용·체크카드 결제실적 | 3,000,000 | 300,000 |
| 여행스케치_남도투어적금 | 광주은행 | 신용·체크카드 사용실적 300만원 이상 | 3,000,000 | 300,000 |

**요구사항**: 금액을 원 단위로 변환 시 만원/천원 단위 표기를 정확히 환산할 것.
예: 300만원=3000000, 30만원=300000. 자릿수 검증 필수.

(참고: `wrong_cases`에는 이 외에도 threshold/rate_bonus 불일치가 몇 건 더 있으나 — 정답이
누락되었거나(`actual: null`), 10배 관계가 아닌 값 차이(예: 0.85 vs 0.7) — 이번 "자릿수 버그"
카테고리와는 원인이 다른 별개 이슈이므로 여기서는 제외했다.)

## 2. UNCONDITIONAL 남발 — 실제 조건인데 "조건 아님"으로 뭉갬 (15건)

`UNCONDITIONAL`은 "가입자 전원에게 적용, 행동과 무관"인 경우에만 써야 하는데, 원문에 명확한
트리거(회차·시점·나이·동의여부·인증여부)가 있는데도 이 값으로 뭉개는 사례가 다수.

| 상품 | 조건 | 원문 근거 | 기대 type |
|---|---|---|---|
| J정기예금(제주은행) | Jbank 로그인 | "계약기간의 1/2이상 매월 Jbank로그인 시" | CHANNEL |
| JB123 정기예금(전북은행) | 자동재예치 회차우대 | "1회차 0.1%, 2회차 0.2%, 3회차 0.3%" | LOYALTY |
| 신한My플러스 정기예금 | 정기예금 미보유 | "정기예금 미보유 : 연 0.1%" | FIRST_TRADE |
| 신한My플러스 정기예금 | 소득이체 | "소득이체 : 연 0.1%" | SALARY_TRANSFER (자원도 누락) |
| NH왈츠회전예금 II | 트리플회전우대 | "4회전기간부터 0.1%p" | LOYALTY |
| NH내가Green초록세상예금 | 손하나로인증 등록 | "손하나로인증 서비스 등록 : 0.1%p" | CHANNEL |
| NH내가Green초록세상예금 | 온실가스 서약동의 | "온실가스 줄이기 실천서약서 동의 : 0.1%p" | OTHER |
| NH내가Green초록세상예금 | 통장 미발급 | "통장미발급 : 0.1%p" | OTHER |
| NH고향사랑기부예금 | 기부금 납부 | "고향사랑기부금 납부고객 우대 : 0.3%p" | OTHER |
| NH고향사랑기부예금 | 연령대(65세이상/19~34세) | "2-1. 만65세 이상... / 2-2. 만19~34세..." (2개 별개 조건, 정답지도 원자분리 완료) | OTHER × 2 |
| Sh해양플라스틱Zero!예금 | 자동이체 출금실적 | "자동이체 출금실적 : 0.1%" | AUTO_TRANSFER |
| Sh해양플라스틱Zero!예금 | 봉사활동/상품홍보 | "봉사활동 또는 상품홍보 : 0.15%" | OTHER |
| Sh해양플라스틱Zero!예금 | 입출금통장 최초신규 | "입출금통장 최초신규 : 0.1%" | FIRST_TRADE |
| Sh해양플라스틱Zero!예금 | 해양플라스틱감축서약 | "해양플라스틱감축서약 : 0.1%" | OTHER |
| 여행스케치_남도투어적금 | 관광지 방문인증 | "당행이선정한 전라남도 관광지 방문 인증시" | OTHER |

**요구사항**: 조건부 트리거 문구(숫자/회차/나이/동의/인증/서약 등 사람이 특정 행동을 해야
충족되는 문구)가 있으면 절대 `UNCONDITIONAL`로 분류하지 말 것 — 있으면 가장 가까운 type을
고르도록 프롬프트에 명시. `UNCONDITIONAL`은 원문에 조건 서술이 전혀 없고 "가입만 하면 전원
적용"인 경우로 예시를 좁혀서 제시.

## 3. 자원 오태깅 — 원문에 근거 없는 resource를 갖다붙임 (16건)

가장 심각한 카테고리. 특히 "무관한 카드/급여 카테고리로 잘못 연결"하는 패턴이 반복됨.

| 상품 | 조건 | 원문 근거 | 파서 오태깅 | 문제 |
|---|---|---|---|---|
| 스마트모아Dream정기예금 | 1천만원 이상 가입 | "1년미만, 1천만원이상 0.10%p" | SALARY_TRANSFER | 원문에 급여 언급 자체가 없음 |
| 스마일드림 정기예금 | 체크카드 보유 | "탐나는전 체크카드 보유고객" | CARD_BUDGET | 보유(binary)일 뿐 결제금액 아님 → NONE이어야 함 |
| 스마일드림 정기예금 | 적금 상품 보유 | "김만덕나눔적금 보유 또는... 만기 해지고객" | CARD_BUDGET | 카드와 무관한 적금 상품 보유 |
| BNK더조은정기예금 | 오픈뱅킹 가입 | "경남은행 오픈뱅킹 서비스를 가입한 경우" | CARD_BUDGET/PRODUCT_HOLDING | 오픈뱅킹 가입 ≠ 카드 |
| BNK더조은정기예금 | 쿠폰 등록 | "신규시 금리우대쿠폰을 등록한 경우" | CARD_BUDGET/CARD_ISSUE | 쿠폰 등록 ≠ 카드 발급 |
| BNK더조은정기예금 | 자동재예치 가입 | "자동재예치를 통해 가입한 경우" | AUTO_TRANSFER | **"자동재예치"≠"자동이체"** — 완전히 다른 개념 |
| NH내가Green초록세상예금 | 적금 동시보유 | "NH내가Green초록세상적금 동시 보유" | CARD_BUDGET | 카드와 무관한 적금 보유 |
| 우리SUPER주거래적금 | 공과금 자동이체 출금 | "공과금 자동이체 출금: 0.3%p" | SALARY_TRANSFER | **사용자 지적 사례** — 공과금≠급여 |
| WON적금 | 통장 연결가입 | "우리꿈통장, WON통장에 연결하여 가입" | SALARY_TRANSFER | 계좌 연결 ≠ 급여이체 |
| WON적금 | 오픈뱅킹 타행계좌 등록 | "오픈뱅킹 서비스에 타행계좌가 등록" | SALARY_TRANSFER | 오픈뱅킹 등록 ≠ 급여이체 |
| 해피라이프_여행스케치적금V | 타 상품 동일자가입 | "여행스케치외화적금V 동일자가입" | SALARY_TRANSFER | 상품 동시가입 ≠ 급여이체 |
| VIP플러스적금 | 정기예금 500만원 가입유지 | "정기예금 500만원이상... 가입하고 만기일 전일까지 유지" | CARD_BUDGET/SALARY_TRANSFER | 실제는 예치금액(CASH_BALANCE) 자원인데 무관한 카테고리로 감 |
| MZ 플랜적금 | 목표금액 달성 | "목표 금액 달성:0.50%" | SALARY_TRANSFER | 적금 목표금액 ≠ 급여이체 |
| 사이버우대매일부금 | 비대면채널 신규 | "비대면채널 신규시 0.1%p" | SALARY_TRANSFER | 채널 가입 ≠ 급여이체 |
| 사이버우대매일부금 | 직장인/주거래통장 가입 | "탐나는 J 직장인통장" | CARD_BUDGET | 통장 보유 ≠ 카드 예산 |
| 사이버우대매일부금 | 파킹통장 가입 | "달리자 파킹통장 가입 고객" | CARD_BUDGET | 통장 보유 ≠ 카드 예산 |

**요구사항**:
1. 원문에 명시된 자원만 태깅한다. 급여 언급이 없으면 `SALARY_TRANSFER` 금지, 카드 언급이
   없으면 `CARD_BUDGET` 금지 등 — resource는 원문에 해당 자원(카드결제/급여이체/평잔/예치금)이
   **명시적으로 언급된 경우에만** 부여하고, 언급이 없으면 절대 추론하지 말 것 (스키마 문서의
   "원문에 없는 정보는 추측 금지" 원칙을 resource 필드에도 명시적으로 강조).
2. "보유/가입/등록"류 **단순 소유·가입 여부 조건**(카드 보유, 상품 보유, 서비스 가입/등록)은
   자원을 소모하는 게 아니므로 resource=NONE. 소진되는 실적(카드 결제액, 급여 이체액, 평잔)과
   구분해서 예시를 추가.
3. "자동재예치"(예금을 만기에 자동으로 다시 예치)와 "자동이체"(공과금 등 정기 출금)는 이름이
   비슷해 보여도 다른 개념 — 프롬프트에 명시적 구분 예시 추가.

## 보류 — 이력조건 resource 규칙 (하람 확인 대기, 이번 라운드 제외)

이력·자격 조건(첫거래·해지이력·장기거래·연령 등)에 resource를 `type`과 동일한 값(예:
`FIRST_TRADE|FIRST_TRADE`)으로 채우는 패턴이 별도로 발견되었으나(예: 굿스타트예금 첫거래,
The든든예금 신규·해지 이력, IBK평생한가족통장 최초신규고객, jbank 저금통적금 첫거래 등),
이를 `resource=NONE`으로 통일할지 여부와 `docs/condition-schema-v1.md`의 `FIRST_TRADE`
resource enum 정의를 함께 고칠지는 하람 확인 대기 중이라 이번 문서에는 포함하지 않는다.
확정되면 위 1~3번과 별도 섹션으로 추가한다.
